# 문제해결 방향 #
</br>

1. 이미지 영역(Placeholder) 사전 확보</br>
스크롤이 튀는 가장 큰 이유는 이미지가 들어올 자리가 0px이었다가, 이미지가 로딩되면서 갑자기 수백 픽셀로 늘어나기 때문입니다.</br>
해당 모듈의 CSS 수정: 이미지가 생성되기 전, 혹은 생성 중일 때 미리 고정된 높이의 투명한 박스나 로딩 애니메이션을 채팅창에 띄워두세요.</br>
예를 들어, min-height: 512px; 같은 속성을 미리 부여하면 이미지가 실제로 나타날 때 전체 페이지 높이 변화가 없으므로 스크롤이 고정됩니다.</br>
</br>

2. '스크롤 고정' 스크립트 활용 (Tampermonkey 등)</br>
RisuAI 내부 로직을 건드리지 못하더라도, 브라우저 확장 프로그램인 **Tampermonkey(그리스몽키)**를 사용해 사용자 측에서 스크립트를 주입할 수 있습니다.</br>
작동 원리: 채팅창 영역(div 등)에 MutationObserver를 걸어둡니다.</br>
새로운 이미지 요소가 추가될 때마다 현재 스크롤 위치를 강제로 고정하거나, 사용자가 보고 있던 위치를 유지하도록 보정하는 코드를 작성할 수 있습니다.</br>
</br>

3. 이미지 출력 방식의 변경 (지연 로딩 방지)</br>
이미지가 "차례대로" 나타나는 방식이 오히려 독이 될 수 있습니다.</br>
Base64 인코딩 사용: 만약 이미지가 완전히 생성된 직후에 데이터를 넘겨준다면, src="url" 대신 src="data:image/png;base64,..." 형태의 Base64 데이터를 사용해 보세요.</br>
브라우저가 외부 파일을 다운로드하며 높이를 재계산하는 과정을 생략하고 즉시 렌더링하므로 튐 현상이 줄어듭니다.</br>
</br>

4. UI 구성 요소 추가: "마지막 이미지로 이동" 버튼</br>
스크롤 문제를 완벽히 막기 어렵다면, 사용자의 편의성을 높이는 방향입니다.</br>
이미지가 생성될 때 채팅창 한구석에 [생성된 이미지 보기] 같은 플로팅 버튼(Floating Button)을 띄워주는 기능을 모듈에 추가하세요.</br>
클릭 시 해당 이미지 요소로 scrollIntoView()를 실행하게 만들면 수동 스크롤의 번거로움을 크게 줄일 수 있습니다.</br>
</br>
